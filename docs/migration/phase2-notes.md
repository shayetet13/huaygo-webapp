# Phase 2 — Postgres/Supabase swap: notes & deviations from the approved plan

**สถานะ: ✅ เสร็จสมบูรณ์และ verify กับ Supabase จริงแล้ว (2026-07-11)**

## สิ่งที่ทำ

- `backend/src/db/postgresClient.ts` — implement `DbClient` interface เดียวกับ `db/client.ts` (SQLite) บน `pg`
- `backend/src/db/sqlTranslate.ts` — แปลง SQLite-isms (`datetime()`, `date()`, `julianday()`, named `@param`) เป็นสำเนียง Postgres แบบ regex ที่ปิดชุดแน่นอน (ทดสอบครบทุก pattern ใน `__tests__/sqlTranslate.test.ts`, 18 เคส)
- `backend/src/db/postgresSchema.sql` + `pgHelpers.sql` — DDL แปลจาก schema.sql + helper function `now_local()`/`now_local_ts()` (Asia/Bangkok)
- `backend/src/db/index.ts` — เลือก backend อัตโนมัติจาก `DATABASE_URL`: มีค่า → Postgres, ไม่มี → SQLite (เดิม)
- `backend/src/scripts/migrateToPostgres.ts` — ย้ายข้อมูล SQLite → Postgres, idempotent (TRUNCATE ก่อน insert), รายงาน row-count parity, `npm run migrate:pg`
- แก้ 2 จุดที่ใช้ `INSERT OR IGNORE` (ไม่ portable) เป็น `ON CONFLICT ... DO NOTHING` (portable ทั้งสอง backend)
- แก้ `sqlite_sequence` DELETE ใน factory-reset เป็น `DbClient.resetAutoIncrement()` (abstract ต่อ backend)
- ปิดช่องโหว่: `lottery_types.name` ไม่เคยมี unique constraint (bug เดิม) — เพิ่ม unique index ทั้งสอง backend (dedupe ก่อนบน SQLite)

## ⚠️ เบี่ยงจากแผนที่อนุมัติไว้ — เหตุผล

แผนเดิมเขียนไว้ว่า "SQLite TEXT datetime → timestamptz" และ "INTEGER booleans → boolean" แต่ระหว่างimplement เลือก **เก็บ TEXT datetime และ INTEGER 0/1 ไว้เหมือนเดิมทั้งสอง backend** แทน เพราะ:
- โค้ดเบสมี `date(col)`, `substr(date,1,7)`, string comparison กับ datetime string อยู่หลายสิบจุด (`WHERE created_at >= ?` เทียบ string ตรงๆ) — การเปลี่ยนเป็น `timestamptz`/`boolean` จริงจะต้องไล่แก้ query เกือบทุกไฟล์เป็นรอบที่สอง (รอบแรกคือ Phase 1 async) เพิ่มความเสี่ยงโดยไม่ได้ประโยชน์เชิงพฤติกรรมทันที
- การ mirror type แบบ 1:1 (TEXT→TEXT, INTEGER→INTEGER, REAL→DOUBLE PRECISION) ทำให้ query string เดิมรันได้ทั้งสอง backend ผ่าน `sqlTranslate.ts` shim เพียงจุดเดียว แทนที่จะกระจายการแก้ไปทั่วโค้ด
- ปรับปรุงเรื่อง type ให้ถูกต้องตามหลักการ (timestamptz จริง, boolean จริง) เก็บไว้เป็นงาน cleanup แยกทีหลังได้ ไม่ผูกกับ migration นี้

หากต้องการให้ทำตามแผนเดิม (native timestamptz/boolean) แจ้งได้ — เป็นงานเพิ่มอีกรอบเดินตามไฟล์เดิมทั้งหมดอีกครั้ง

ปัญหาเชื่อมต่อก่อนหน้านี้เกิดจากเดา pooler region ผิด (ลองทุก region ของ `aws-0-*` ไม่ผ่านสักอัน) — connection string จริงของโปรเจกต์นี้คือ **`aws-1-ap-southeast-1`** (ไม่ใช่ `aws-0`) และใช้ port **5432** (session mode) ไม่ใช่ 6543:
```
postgresql://postgres.vwwemktymekjhtkccojf:<url-encoded-password>@aws-1-ap-southeast-1.pooler.supabase.com:5432/postgres
```
บทเรียน: เวลาเดา pooler connection string อย่าเดาแค่ region — เลข generation (`aws-0` vs `aws-1`) ก็ต่างกันได้ต่อโปรเจกต์ ควรคัดลอกจาก Supabase Dashboard → Project Settings → Database เสมอแทนการเดา

**พบด้วย:** ตอน debug เจอว่าโปรเจกต์นี้มี custom function `huay_now_local()`/`rls_auto_enable()` อยู่ก่อนแล้ว (จาก setup ครั้งก่อนหน้า) — ไม่ชนกับ schema ที่สร้างในรอบนี้ (ชื่อฟังก์ชันคนละชื่อ) แต่น่าจะเป็นร่องรอยจากความพยายามครั้งก่อน ควรเช็คว่ามีอะไรอื่นค้างอยู่ไหมก่อน production จริง

## บั๊กที่เจอระหว่าง verify จริง (แก้แล้ว)

1. **`GENERATED ALWAYS AS IDENTITY` ปฏิเสธการ insert id ตรงๆ** — migration script ต้อง preserve id เดิมจาก SQLite แต่ Postgres บล็อกไว้โดย default เปลี่ยนเป็น `GENERATED BY DEFAULT AS IDENTITY` ทุกตาราง (อนุญาตทั้ง auto-generate ปกติ และ insert ทับตรงๆ ตอน migrate)
2. **`COUNT(*)`/`SUM(int_col)` คืนเป็น BIGINT → pg driver parse เป็น string ไม่ใช่ number** — ทำให้ `dashboardStats.service.ts` ที่บวกเลขตรงๆ (`a.betCount + b.betCount`) ได้ string concatenation แทนบวกเลขจริง (`"0"+"0"="00"`) เจอจาก smoke test จริง ไม่ใช่จาก unit test (unit test ใช้ SQLite ที่คืน number ปกติอยู่แล้ว) — แก้ด้วย `types.setTypeParser(20, parseInt)` ใน `postgresClient.ts`

ทั้งสองจุดนี้เป็นตัวอย่างว่าทำไม Phase 2 ต้อง live-verify จริง ไม่ใช่แค่ unit test ผ่าน — สอง bug นี้ unit test ไม่มีทางจับได้เพราะ mock/SQLite ไม่มีพฤติกรรมต่างจาก Postgres ตรงจุดนี้

- Boot ซ้ำหลัง migrate → dashboard/admin bets endpoint แสดงข้อมูลจริงที่ migrate มาถูกต้องครบ (2 bets จริง, ยอดเดือน/ปีตรง)
